## 一、这是什么

`diag_m4.m` 逐行复刻 `demo_sins_dr.m` 的组合链（SINS + DR 锚定 + 22 维 KF），
只在**每次量测更新**（每 0.1s 一次）时打印一行关键中间量。
它是「卡尔曼滤波器的手术灯」——让你（或我）能看见滤波器每步在想什么。

```
量测#100 t=10.0s | z(m)=[+0.98,+1.12,+1.04] | xfb(m/s)=+0.0000,+0.0000,+0.0002
      xk(φ)=+0.5,-0.8,-0.1" | xk(δv)=+0.000,+0.000,+0.000 | δr(m)=+0.5,+0.5,+0.3 | P66=9.361e-03 P67=-3.398e-04 P69=+1.899e-01 | dKod=-0.0010 dT=-0.0ms
```

**打印节奏**：`量测#1~#5`（t=0.1~0.5s）+ `#100 起每 50 次`（t=10s 起每 5s）。

## 二、逐列含义（字典）

| 字段 | 含义 | 单位 | 通俗解释 |
|---|---|---|---|
| `量测#100` | 第 100 次量测更新 | 次 | 每 0.1s 一次 → #100 = t=10s |
| `t=10.0s` | 仿真时刻 | s | 轨迹走到哪 |
| `z(m)=[东,北,高]` | **量测新息** = SINS位置 − DR位置 | m | 两条定位链差多远（喂给 KF 的观测） |
| `xfb(m/s)=[δvE,δvN,δvU]` | **反馈量**（清零前抓拍） | m/s | KF 这次要「拉」SINS 速度多少 |
| `xk(φ)=[pitch,roll,yaw]"` | KF 估计的姿态误差 | 角秒 | 1° = 3600" |
| `xk(δv)` | 反馈**后**的速度误差 | m/s | 反馈完清零 → 恒 0（正常） |
| `δr(m)=[lat,lon,h]` | KF 估计的位置误差 | m | 认为 SINS 位置偏了多少 |
| `P66` | **δv(3) 的方差** = P(6,6) | (m/s)² | 垂直速度估计的不确定度——**xfb(3) 的直接来源** |
| `P67` | δv(3) 与 δr(1) 的互协方差（转米） | m·m/s | 垂直速度↔纬度误差的相关性 |
| `P68` | δv(3) 与 δr(2) 的互协方差（转米） | m·m/s | 垂直速度↔经度误差的相关性 |
| `P69` | δv(3) 与 δr(3) 的互协方差 | m·m/s | 垂直速度↔高度误差的相关性 |
| `dKod` | 估计的里程计刻度误差 | 无量纲 | 真值 +0.05（5%），估计应趋近 |
| `dT` | 估计的时延误差 | ms | 真值 0，估计应趋近 0 |

> **为什么盯 xfb 和 P66？** 卡尔曼量测更新的本质是
> `修正量 = K · z`，而增益 `K ≈ P·Hᵀ/(H·P·Hᵀ+R)`。
> 垂直通道的增益大小由 **P(6,6)（δv₃ 方差）** 主导——P66 越大，一次量测拉的越多。
> 所以 xfb(3) 偏大 30~100% 的根源，要么是 P 演化偏大（kffk 的 F 矩阵），
> 要么是 K 计算偏大（kfupdate）。**P66 一行就能区分这两者。**

## 三、怎么看「正常 / 异常」

**正常（Python 参考 45.5 m 的行为）**：
- z 三个分量随轨迹平滑演化，垂直分量静止段缓慢增长后**趋平**（≈+2.2 m 稳住）；
- xfb 很小（≤0.001 m/s），且**先增后减**（把初始 0.1 m/s 的垂直速度轻轻压住即停）；
- P66 演化规律：**#100 ≈9.4e-3 → #200 峰值 ≈2.3e-2 → 之后单调衰减**（量测持续压低不确定度）；
- φ 估计量级正常，dKod 收敛到 +0.05 附近，dT 收敛到 0 附近。

**异常（MATLAB 267 m 的行为）**：
- z 垂直分量增长到 ~+1.9 m 后**掉头持续下降**（被反馈修过头、修成负的）；
- xfb 垂直分量**系统性偏大 30~100%**（修得太多）；
- 其余量（φ/δr/dKod/dT）仍与参考一致 → 问题**只在垂直通道的 KF 增益**。

## 六、怎么用这份输出定位 bug（判断树）

```
你贴回 MATLAB 的 diag_m4 输出后，按下面两步对比：

① P66 / P67 / P69 是否与上表一致？
   ├─ 一致 → KF 的 P 演化没问题，问题在量测更新的 K 计算
   │          （查 kfupdate.m 的 S=H·P·Hᵀ+R / K=P·Hᵀ·S⁻¹）
   └─ 不一致（比如 #200 时 P66=0.04 而非 0.0227）
      → P 演化偏大，问题在 kffk.m 的 F 矩阵（第 6 行 δv₃ 相关块）
        或 kfupdate.m 的时间更新 P=Φ·P·Φᵀ+Q

② 无论 P 是否一致，再看 xfb(3)：
   ├─ P 一致但 xfb 偏大 → K 行向量某列符号/量级错
   └─ P 不一致 → 沿 P 的传播链向上查 F 矩阵对应元素
```

**结论格式**：贴回时按 `量测#XXX | P66=... P67=... P69=... | xfb(3)=...` 即可，
我会直接对照上表给出结论。

## 附：为什么 MATLAB 与 Python 会「前 100 次一致、之后分道」

卡尔曼滤波是**闭环**系统：前 10s 两者都由初始 P0/Q/R 主导，数值完全同步；
随后每一步量测都在「用当前的 P 决定修正量 → 修正量改变状态 → 状态改变下一步 z」，
任何微小的 P 差异都会在几秒内被**反馈放大**成可见的轨迹差异。
这正是我们逐步对比 z → xfb → P 的原因：**越靠近根因的量，分道越早**。
